# music_player

MP3 playback engine with hierarchical catalog (Artist → Album → Track) sourced from an `INDEX.JSN` file on the SD card. Uses a dual-task architecture to decouple decoding from DMA feeding.

## Architecture

```
music_player_task (prio 4)        music_feed_task (prio 5)
  SD I/O + minimp3 decode    →    PCM ring buffer    →    audio_manager_write()
                              128 KB StreamBuffer              ↓
                                                         esp_codec_dev_write()
                                                              ↓
                                                         I2S DMA (~33 ms)
```

`music_player_task` decodes MP3 frames and pushes raw PCM bytes into a 128 KB StreamBuffer (≈ 0.74 s of audio at 44.1 kHz stereo). `music_feed_task` runs at higher priority, drains the ring buffer, and feeds the codec via `audio_manager_write()`. The ring buffer decouples SD/decode stalls from the DMA deadline.

## Catalog

Tracks are indexed by flat integer index. The catalog is built once from `INDEX.JSN` (generated by the sync script) and kept in PSRAM for the boot session. The hierarchy (Artist → Album → Track) is navigated through the `music_catalog_*` accessor functions.

`music_player_load_catalog()` mounts the SD card (idempotent) and parses `INDEX.JSN`. Call lazily — it's also triggered automatically on first transport call.

## Playback

All transport functions (`music_player_play`, `toggle_play_pause`, `next`, `prev`) are non-blocking: they enqueue commands to `music_player_task` and return immediately. State changes are observable via `music_player_get_now_playing()`.

## Pause / resume for notifications

When `audio_manager` needs to preempt music for a notification:
1. `pause_for_notify()` sends `CMD_PAUSE` and blocks until the task flushes the ring buffer and closes the codec.
2. After the notification, `resume_after_notify()` sends `CMD_RESUME` (async).
3. The decoder is left open across the pause — resume restores the codec and decoding continues from the same position.

These hooks are registered with `audio_manager` at engine start.

## SD card

The SD card is mounted once on first use and left mounted for the boot session (persistent-mount strategy, consistent with `sd_logger`).

## Dependencies

`esp32_s3_touch_amoled_2_06` (BSP — SD card mount), `audio_manager` (also provides minimp3 headers via its public include path), `settings`, `json`
